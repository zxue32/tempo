# Tempo：美甲店、理发店在线预约平台

一个开放的预约平台：店主自己注册、开店、设置服务和排班，**每家店都有自己的预约链接**，但必须经过你（平台管理员）审核通过后，客人才能预约。

这一版**不涉及任何付款**：不收定金，不在线支付，报表里的营业额只是按价目表估算。以后需要收定金时，在现有的预约流程上加一步就可以。

---

## 功能一览

### 客人这边（不用注册，填手机号就能约）
- 店铺主页：营业中 / 休息状态、服务和价格、加项、技师介绍、营业时间、特殊日期、取消政策
- 三步预约：**选服务 → 选技师和时间 → 填信息**
  - 可以选多个服务，加项按服务类别自动筛选，时长自动相加
  - 支持多人同行（每人可以选不同服务，自动分给不同技师，同一时间开始）
  - 可以选“任意技师”，系统自动挑当时最空的人
  - 日期条直接显示每天还剩几个空位，约满的日子会提示“下一个可约日期”
  - 每位技师可以给同一个服务设置自己的时长，时间格子按她的时长计算
  - 可以上传参考图，写备注
  - 记住客人上次填的姓名电话
- 预约成功页：预约编号、加入 Google / Apple / Outlook 日历、导航
- 客人自己改时间、取消（截止时间可设置，默认提前 8 小时）
- 忘了确认邮件：用“预约编号 + 手机号”找回
- 邮件：确认、改时间、取消、前一天提醒（中英双语，按客人预约时的语言发）

### 实时可用时间（这是核心）
- 技师的可约时间 = 排班时间 − 午休 − 已有预约 − 店铺休息 − 提前预约时限
- 例：技师 10:00–18:00 上班，客人约了 15:00–17:00，那么任何会和 15:00–17:00 重叠的开始时间都会立刻消失
- **数据库层面保证不会重复预约**：两个客人同时点同一个时间，只有一个能成功，另一个会提示“这个时间刚被约走”
- 时间都按店铺所在时区计算（包括夏令时切换）

### 按店里的真实规则算（这一版新增）
- **设备**：登记足浴椅、水槽等的数量，给服务指定需要的设备；同一时间用到它的预约不会超过数量（多人同时抢也一样）
- **给散客留位**：线上预约至少留 N 位技师空着给进门的客人，店里自己加的预约不受限
- **“任意技师”怎么分**：按忙闲（当天约得最少的人），或按轮牌（当天接客次数最少的人，可选点名客算不算一轮）
- **不留零碎空档**：网上不显示会留下 15、20 分钟没人能用的时间
- **预约前的问题**：加项可以设成问题（如“现在手上有没有甲胶？”），客人答“是”自动加上卸甲的时间
- **爽约限制**：爽约 N 次后只能打电话约
- 所有预约写入都按店排队处理，这些全店规则不会被同时下单绕过

### 作品集
- 店主批量上传作品照片，标上技师和服务；店铺页显示作品，客人点开大图可以“约这个款”，自动选好服务和技师，照片作为参考图带给技师
- 每位技师的作品可以单独查看
- 照片可以打标签（长度、风格、颜色），客人在作品页按技师 / 长度 / 风格 / 颜色点一下就能筛

### 互动功能（2026-10-27 新增）
- **设计你的美甲**：店铺页和预约第 3 步都有一只手的示意图，客人点甲型、长度、颜色、质感、花样马上看到效果；设计随预约发给技师（日历详情、“我的一天”里有图和文字说明，并自动生成一张参考图）。颜色来自店里的“色板”，没设置时用内置的 18 种
- **色板**：后台按色号维护发色和美甲颜色（名称、色号、颜色、渐变第二色、效果图）。理发店的店铺页多一块“发色”，客人点色块看效果，带着色号去预约
- **日历拖动**：按住预约拖到别的时间或别的技师（手机长按半秒），松手后确认；放不下的位置会变红
- **排班一周总览**：每位技师一条色条，拖两端改上下班、拖中间整条移动、点空白处加班次、× 删掉；午休仍在表格视图改
- **技师个人主页**：`/店铺链接/t/技师` 有照片、介绍、擅长、作品、评分和“约她”按钮；在“预约链接”页可复制。员工页可填“擅长”、可关闭主页
- **客人评分**：预约完成后，客人在自己的预约页打 1–5 星并留一句话（每次预约一次）；满 3 个评分后主页显示平均星级，留言只有店里看得到
- **客人偏好卡**：客人档案里记常用颜色、甲型、长度、质感、风格、发色、发型、常约技师和注意事项（全是点选）；日历详情、“我的一天”、新建预约（输入手机号后）都会显示，常约技师会自动选上。客人自己的手机也会记住上次的设计 / 发色（只存在客人手机上），再次预约时一点带上；“再约一次”链接也会带着上次的设计

### 用数据证明有用（这一版新增）
- **真实时长**：技师点“开始服务 / 完成”，按技师 × 服务统计 P50 / P80，一键改成建议时长
- **客人确认**：提醒邮件里有“确认我会来”，后台显示谁确认了、谁还没确认
- **候补名单**：约满时客人可以候补；有人取消，自动按先后顺序邮件通知
- **试点数据页**：上线前 vs 最近 30 天（爽约率、线上占比、电话数、空闲时间）、预约漏斗（客人在哪一步离开，只记匿名次数）、双轨对账记录、纸本试算（把纸本历史录进来，检验设置是否符合现实）、每晚自动检查、候补名单
- **可打印的每日对账单**：双轨试运行期间和纸本逐条对

### 店主后台
- **日历**：按天看所有技师的时间轴；点空白处加预约（到店散客 / 电话预约 / 占用时间）；点预约可以完成、标记未到店、改时间换人、改项目、取消（可选发邮件通知客人）、恢复，能看到改动记录
- **我的日程**：技师用手机看自己当天的预约、空档、下一位客人，可以点“完成 / 未到”
- **预约列表**：按日期、技师、状态、来源、姓名/手机号/编号筛选，导出 CSV（Excel 可直接打开）
- **客人**：自动建立客人档案，看来店次数、未到店次数、最近一次、下次预约、估算消费；可写内部备注、禁止某个客人在线预约；偏好卡（见上）
- **排班**：每周不一样的排班，复制上周、按默认填充、单独改某天、午休；保存时提示和已有预约冲突的地方；特殊日期（节假日休息、提早关门）
- **员工**：技能（会做哪些服务）、个人时长、颜色、头像、简介、提成比例、是否接受在线预约、默认每周班表、给员工生成一次性的加入链接（员工登录后只能看自己的日程）
- **服务项目**：服务和加项，时长、价格、“起价”、分类、上下架、是否可在线约、排序
- **报表**：本周/本月/上月/自定义；预约数、完成、未到店率、取消、估算营业额、排班利用率；每位技师的完成数、服务时长、估算营业额和提成；每天预约数、热门服务、预约来源、新客 / 回头客
- **预约链接**：复制链接、二维码下载、网站“预约”按钮代码、每位技师的专属链接和个人主页链接
- **色板**：发色 / 美甲颜色，按色号排序，可以不显示给客人
- **店铺设置**：店名（中英）、介绍、联系方式、地图链接、4 套主题 + 自定义主色、Logo 和封面、营业时间、预约规则（时间间隔、最少提前多久、最多提前几天、取消截止、清理时间、最多几位同行、是否允许“任意技师”、是否显示价格）、预约须知、通知邮箱、时区和默认语言

### 平台管理员（你）
- 店铺审核队列：草稿 / 待审核 / 需修改 / 已上线 / 未通过 / 已暂停
- 每家店的准备情况、联系方式、营业时间、服务和员工，可以预览店铺页
- 通过上线、退回修改、拒绝、暂停、恢复（退回 / 拒绝 / 暂停必须写原因，会邮件通知店主）
- 修改店铺链接
- **邀请码**：给已经谈好的店发邀请链接，用邀请码注册的店提交后直接上线，不用再审核
- **账号**：查看所有账号和所属的店，生成一次性的重设密码链接，停用账号

## 部署（全部免费）

用到三个免费服务：**GitHub**（放代码）、**Supabase**（数据库，照片也存在里面）、**Netlify**（网站和每小时的定时任务）。发邮件用 **Resend**，可选。登录是网站自己做的（邮箱 + 密码），不依赖 Supabase 的登录功能，所以 Supabase 后台不用做任何设置。

> 为什么用 Netlify 而不是 Vercel：Vercel 的免费版只允许非商业用途，Netlify 的免费版允许商业用途。

### 第 1 步：数据库（Supabase）
1. 在 [supabase.com](https://supabase.com) 新建项目，区域选离店最近的（美国东部选 `East US`）
2. 点项目顶部的 **Connect**，拿两个地址：
   - **Transaction pooler**（端口 6543）→ `DATABASE_URL`
   - **Session pooler**（端口 5432）→ `DIRECT_DATABASE_URL`
3. 建表：在自己电脑上（需要 [Node.js 22](https://nodejs.org)）
   ```bash
   npm install
   cp .env.example .env.local     # 填上面两个地址
   npm run db:migrate
   ```
   以后每次更新代码都再跑一次，已经建好的部分会自动跳过

### 第 2 步：网站（Netlify）
1. [netlify.com](https://www.netlify.com) → **Add new site → Import an existing project** → 选 GitHub 仓库。构建设置已经写在 `netlify.toml` 里
2. **Site configuration → Environment variables**，按 `.env.example` 添加：
   - `DATABASE_URL`、`DIRECT_DATABASE_URL`（勾选 *Contains secret values*）
   - `NEXT_PUBLIC_SITE_URL`：网站地址，不要以 `/` 结尾
   - `PLATFORM_ADMIN_EMAILS`：你自己的邮箱
   - `ADMIN_SETUP_CODE`：一串只有你知道的字符，注册管理员账号时要填
   - `CRON_SECRET`：一串很长的随机字符
3. **Deploys → Trigger deploy** 重新部署一次
4. **Site configuration → Access & security → Visitor access** 确认没有开启“只有团队成员能访问”
5. 带保密标记（*Contains secret values*）的变量，作用范围要选 **Production**（保密值不能用在本地开发环境，选“所有环境”会保存失败）

> `netlify.toml` 里写明了 Netlify 的 Next.js 运行环境（`@netlify/plugin-nextjs`）。不要删：通过上传方式部署时，Netlify 不会自动加上它，网站会整站显示 404。

每小时的提醒邮件和每晚自检由 `netlify/functions/cron.mjs` 自动运行，不需要另外设置。

### 第 3 步：邮件（Resend，可选但建议）
1. [resend.com](https://resend.com) 注册，免费版每天 100 封
2. **API Keys** → 新建 → 填到 Netlify 的 `RESEND_API_KEY`
3. 有自己的域名：在 **Domains** 里验证，`EMAIL_FROM` 写 `店名 <bookings@你的域名>`；还没有域名时先写 `Tempo <onboarding@resend.dev>`（只能发给你自己）
4. 不设置也能正常预约，只是不发邮件。忘记密码时，由你在 `/admin` → **账号** 里生成一次性的重设密码链接，发给对方

> Supabase 免费项目一周没有任何访问会自动暂停。每小时的定时任务会访问一次数据库，一般不会被暂停；真的暂停了，在 Supabase 后台点一下恢复就行。

## 上线后怎么用

### 你（平台管理员）
1. 打开 `/signup`，用 `PLATFORM_ADMIN_EMAILS` 里的邮箱注册，展开“我是平台管理员”，填 `ADMIN_SETUP_CODE`。只有同时满足这两点的账号才有管理员权限
2. 打开 `/admin` → **邀请码 → 新建**，备注写店名，把生成的链接发给已经谈好的店
3. 没有邀请码自己注册的店，提交后会出现在“待审核”，你检查后点“通过，上线”
4. **账号**：查看所有账号，帮忘记密码的人生成重设链接，停用账号

### 店主
1. 打开邀请链接注册 → 填店名、链接、地址、时区 → 创建
2. 按“开店清单”走一遍：服务和价格 → 员工和技能 → 排班 → 营业时间 → 外观
3. 点“提交审核”（用邀请码的店直接上线）
4. 在“预约链接”页面复制链接、下载二维码，放到 Instagram、Google 地图、门口

### 技师
店主在“员工”页面打开某位技师 → **生成加入链接**，用短信或微信发给她。她打开链接、注册或登录、点“加入”，手机上就能看到“我的日程”。链接只能用一次；发错了就再生成一个，旧的会失效。

## 本地开发

```bash
npm install
cp .env.example .env.local
# 只填 DATABASE_URL 和 DIRECT_DATABASE_URL（可以用本地 Postgres），再加：
# PLATFORM_ADMIN_EMAILS=admin@example.com
# ADMIN_SETUP_CODE=任意字符
# DEV_FAKE_AUTH=1        ← 可选：输入邮箱就能登录，不用密码（只在开发模式有效）
npm run db:migrate
npm run dev
```
打开 http://localhost:3000 。上传的照片存在数据库里（设置了 `SUPABASE_URL` 和 `SUPABASE_SECRET_KEY` 时改存 Supabase Storage），没有设置 Resend 时邮件内容会打印在终端里。

### 示范店
```bash
DATABASE_URL=postgres://… OWNER_PASSWORD=店主密码 node scripts/seed-demo.mjs demo-nails 你的邮箱
```
生成一家已上线的“Demo Nails”：3 位技师、5 个服务、3 周排班，可以直接打开 `/demo-nails` 试约。

### 测试
```bash
npm run typecheck                                # 类型检查
DATABASE_URL=postgres://…/tempo_test npm test    # 见下（会清空这个测试库）
npm run e2e                                      # 浏览器全流程 + 无障碍检查
```
- **随机对照测试**（`tests/engine.property.test.ts`）：随机生成上千种排班、预约、设备、规则组合，和一个逐分钟检查的“笨办法”对照：系统推荐的时间必须正好等于规则允许的时间，不多也不少。`PROPERTY_RUNS=8000` 可以跑更多
- **数据库测试**：并发抢同一个时间、设备抢占、散客留位、爽约限制、候补通知、真实时长统计、纸本试算、每晚自检
- **浏览器测试**：开店 → 审核 → 预约 → 改时间 → 取消；作品集 → 约这个款 → 预约前问题 → 候补 → 客人确认 → 开始 / 完成 → 试点数据页；每个页面跑 axe 无障碍检查（WCAG 2.1 AA）
- **压力测试**（只对测试库）：
  ```bash
  npm run build
  LOADTEST_DISABLE_RATE_LIMIT=1 DATABASE_URL=… npx next start -p 3200   # 保持运行，另开一个终端执行下一行
  DATABASE_URL=… node scripts/loadtest.mjs http://localhost:3200 demo-nails 40
  ```
  40 个客人同时抢同一个时间，只有能做的人数那么多会成功，其余收到“刚被约走”，不能出现服务器错误或重复预约。**正式网站绝对不要设置 `LOADTEST_DISABLE_RATE_LIMIT`。**
- **线上冒烟测试**（只用浏览器，不碰数据库）：在正式网站上走一遍注册 → 开店 → 审核 → 预约 → 改时间 → 取消 → 重新登录。会留下一家名字以 `live-test-` 开头的测试店和两个账号，测完要手动删掉
  ```bash
  LIVE_URL=https://你的网址 LIVE_ADMIN_EMAIL=管理员邮箱 LIVE_SETUP_CODE=管理员注册码 npx playwright test -c e2e/live/live.config.ts
  ```

## 代码结构

```
db/migrations/        数据库表结构（含防重复预约约束）
scripts/migrate.mjs   建表脚本
src/lib/engine.ts     可用时间计算（纯函数，前后端共用）
src/lib/bookings.ts   创建 / 修改 / 取消预约（事务 + 并发保护）
src/lib/availability.ts  从数据库组装某几天的可约时间
src/lib/data/         店铺、服务、员工、排班、报表、设备、作品集、色板、候补、试点数据的数据库读写
src/components/NailArt.tsx     美甲示意图（SVG）和设计的文字说明
src/components/NailDesigner.tsx  “设计你的美甲”的选择器，设计转成 PNG 参考图
src/components/PrefChips.tsx   客人偏好卡的小标签（日历、我的一天、客人页共用）
src/lib/replay.ts     纸本试算：用今天的设置重排历史预约
src/lib/waitlistNotify.ts  取消后通知候补
docs/试点手册.md       三家店的现场试点手册
src/lib/email.ts      邮件模板和发送
src/lib/i18n/         中英文文案
src/app/[slug]/       客人看到的店铺页、预约流程、找回预约
src/app/b/[token]/    客人的预约管理页（改时间、取消）
src/app/dashboard/    店主后台
src/app/admin/        平台管理员后台
src/app/api/          给前端用的接口、提醒邮件定时任务
src/lib/accounts.ts   账号、登录会话、重设密码链接
netlify/functions/    每小时运行的定时任务
tests/  e2e/          自动测试
```
