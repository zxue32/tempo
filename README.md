# Tempo：美甲店、理发店在线预约平台

一个开放的预约平台：店主自己注册、开店、设置服务和排班，**每家店都有自己的预约链接**，但必须经过你（平台管理员）审核通过后，客人才能预约。

这一版**不涉及任何付款**：不收定金，不在线支付，报表里的营业额只是按价目表估算。以后需要收定金时，在现有的预约流程上加一步就可以。

---

## 功能一览

### 客人这边（不用注册，填手机号就能约）
- 店铺主页：营业中 / 休息状态、服务和价格、加项、技师介绍、营业时间、特殊日期、取消政策
- 三步预约：**选服务 → 选技师和时间 → 填信息**
  - 可以选多个服务，加项按服务类别自动筛选，时长自动相加
  - 支持多人同行（每人可以选不同服务，自动分给不同技师，同一时间开始）
  - 可以选“任意技师”，系统自动挑当时最空的人
  - 日期条直接显示每天还剩几个空位，约满的日子会提示“下一个可约日期”
  - 每位技师可以给同一个服务设置自己的时长，时间格子按她的时长计算
  - 可以上传参考图，写备注
  - 记住客人上次填的姓名电话
- 预约成功页：预约编号、加入 Google / Apple / Outlook 日历、导航
- 客人自己改时间、取消（截止时间可设置，默认提前 8 小时）
- 忘了确认邮件：用“预约编号 + 手机号”找回
- 邮件：确认、改时间、取消、前一天提醒（中英双语，按客人预约时的语言发）

### 实时可用时间（这是核心）
- 技师的可约时间 = 排班时间 − 午休 − 已有预约 − 店铺休息 − 提前预约时限
- 例：技师 10:00–18:00 上班，客人约了 15:00–17:00，那么任何会和 15:00–17:00 重叠的开始时间都会立刻消失
- **数据库层面保证不会重复预约**：两个客人同时点同一个时间，只有一个能成功，另一个会提示“这个时间刚被约走”
- 时间都按店铺所在时区计算（包括夏令时切换）

### 按店里的真实规则算（这一版新增）
- **设备**：登记足浴椅、水槽等的数量，给服务指定需要的设备；同一时间用到它的预约不会超过数量（多人同时抢也一样）
- **给散客留位**：线上预约至少留 N 位技师空着给进门的客人，店里自己加的预约不受限
- **“任意技师”怎么分**：按忙闲（当天约得最少的人），或按轮牌（当天接客次数最少的人，可选点名客算不算一轮）
- **不留零碎空档**：网上不显示会留下 15、20 分钟没人能用的时间
- **预约前的问题**：加项可以设成问题（如“现在手上有没有甲胶？”），客人答“是”自动加上卸甲的时间
- **爽约限制**：爽约 N 次后只能打电话约
- 所有预约写入都按店排队处理，这些全店规则不会被同时下单绕过

### 作品集（这一版新增）
- 店主批量上传作品照片，标上技师和服务；店铺页显示作品，客人点开大图可以“约这个款”，自动选好服务和技师，照片作为参考图带给技师
- 每位技师的作品可以单独查看

### 用数据证明有用（这一版新增）
- **真实时长**：技师点“开始服务 / 完成”，按技师 × 服务统计 P50 / P80，一键改成建议时长
- **客人确认**：提醒邮件里有“确认我会来”，后台显示谁确认了、谁还没确认
- **候补名单**：约满时客人可以候补；有人取消，自动按先后顺序邮件通知
- **试点数据页**：上线前 vs 最近 30 天（爽约率、线上占比、电话数、空闲时间）、预约漏斗（客人在哪一步离开，只记匿名次数）、双轨对账记录、纸本试算（把纸本历史录进来，检验设置是否符合现实）、每晚自动检查、候补名单
- **可打印的每日对账单**：双轨试运行期间和纸本逐条对

### 店主后台
- **日历**：按天看所有技师的时间轴；点空白处加预约（到店散客 / 电话预约 / 占用时间）；点预约可以完成、标记未到店、改时间换人、改项目、取消（可选发邮件通知客人）、恢复，能看到改动记录
- **我的日程**：技师用手机看自己当天的预约、空档、下一位客人，可以点“完成 / 未到”
- **预约列表**：按日期、技师、状态、来源、姓名/手机号/编号筛选，导出 CSV（Excel 可直接打开）
- **客人**：自动建立客人档案，看来店次数、未到店次数、最近一次、下次预约、估算消费；可写内部备注、禁止某个客人在线预约
- **排班**：每周不一样的排班，复制上周、按默认填充、单独改某天、午休；保存时提示和已有预约冲突的地方；特殊日期（节假日休息、提早关门）
- **员工**：技能（会做哪些服务）、个人时长、颜色、头像、简介、提成比例、是否接受在线预约、默认每周班表、邀请员工登录（员工只能看自己的日程）
- **服务项目**：服务和加项，时长、价格、“起价”、分类、上下架、是否可在线约、排序
- **报表**：本周/本月/上月/自定义；预约数、完成、未到店率、取消、估算营业额、排班利用率；每位技师的完成数、服务时长、估算营业额和提成；每天预约数、热门服务、预约来源、新客 / 回头客
- **预约链接**：复制链接、二维码下载、网站“预约”按钮代码、每位技师的专属链接
- **店铺设置**：店名（中英）、介绍、联系方式、地图链接、4 套主题 + 自定义主色、Logo 和封面、营业时间、预约规则（时间间隔、最少提前多久、最多提前几天、取消截止、清理时间、最多几位同行、是否允许“任意技师”、是否显示价格）、预约须知、通知邮箱、时区和默认语言

### 平台管理员（你）
- 店铺审核队列：草稿 / 待审核 / 需修改 / 已上线 / 未通过 / 已暂停
- 每家店的准备情况、联系方式、营业时间、服务和员工，可以预览店铺页
- 通过上线、退回修改、拒绝、暂停、恢复（退回 / 拒绝 / 暂停必须写原因，会邮件通知店主）
- 修改店铺链接
- **邀请码**：给已经谈好的店发邀请链接，用邀请码注册的店提交后直接上线，不用再审核

## 免费部署（大约 30 分钟）

需要四个免费账号：**GitHub**（放代码）、**Supabase**（数据库、登录、图片）、**Netlify**（网站）、**Resend**（发邮件，可选）。

> 为什么用 Netlify 而不是 Vercel：Vercel 的免费版只允许非商业用途，Netlify 的免费版允许商业用途。

### 第 1 步：把代码放到 GitHub
1. 在 GitHub 新建一个**私有**仓库（例如 `tempo`）
2. 把这个文件夹里的所有文件上传进去（`.env.local` 不要上传，`.gitignore` 已经排除了）

### 第 2 步：Supabase（数据库 + 登录 + 图片）
1. 打开 [supabase.com](https://supabase.com)，新建项目。区域选离你的店最近的（美国东部选 `East US`）。**数据库密码记下来**
2. 拿数据库地址：点项目顶部的 **Connect**
   - **Transaction pooler**（端口 6543）→ 填到 `DATABASE_URL`
   - **Session pooler**（端口 5432）→ 填到 `DIRECT_DATABASE_URL`
   - 把地址里的 `[YOUR-PASSWORD]` 换成你的数据库密码
3. 建表：在自己电脑上（需要先装 [Node.js 22](https://nodejs.org)）
   ```bash
   npm install
   cp .env.example .env.local     # 然后把上面两个数据库地址填进去
   npm run db:migrate
   ```
   看到 `done, 2 migration(s) applied` 就成功了。以后每次更新代码，都再跑一次 `npm run db:migrate`（已经建好的部分会自动跳过）
4. 登录设置：**Authentication → URL Configuration**
   - Site URL：你的网站地址（第 3 步拿到后再回来填，例如 `https://tempo-xxx.netlify.app`）
   - Redirect URLs：添加 `https://你的网址/auth/callback`
5. 拿 API 钥匙：**Project Settings → API Keys**
   - Project URL → `NEXT_PUBLIC_SUPABASE_URL`
   - Publishable key（`sb_publishable_…`）→ `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
   - Secret key（`sb_secret_…`）→ `SUPABASE_SECRET_KEY`（**只放在服务器端，不要公开**）
6. 图片：**Storage → New bucket**，名字 `media`，勾选 **Public bucket**

> Supabase 自带的登录邮件每小时只能发很少几封。正式使用前，建议在 **Authentication → Emails → SMTP Settings** 里填 Resend 的 SMTP（见第 4 步），这样注册确认、找回密码邮件不会被限流。

### 第 3 步：Netlify（网站）
1. 打开 [netlify.com](https://www.netlify.com)，用 GitHub 登录 → **Add new site → Import an existing project** → 选你的仓库
2. 构建设置会自动识别（`netlify.toml` 已经写好），直接部署
3. **Site configuration → Environment variables**，把 `.env.example` 里的变量一个个加进去（`DEV_FAKE_AUTH` 不要加）
   - `NEXT_PUBLIC_SITE_URL` 填 Netlify 给你的网址（或者你自己的域名）
   - `PLATFORM_ADMIN_EMAILS` 填你自己的邮箱
   - `CRON_SECRET` 填一串很长的随机字符
4. 加完变量后 **Deploys → Trigger deploy** 重新部署一次
5. 回到 Supabase 第 2 步第 4 点，把网址填上

### 第 4 步：Resend（邮件，可选但强烈建议）
1. 打开 [resend.com](https://resend.com) 注册，免费版每天 100 封、每月 3000 封
2. **API Keys** → 新建 → 填到 `RESEND_API_KEY`
3. 有自己的域名：**Domains** 里添加并按提示加 DNS 记录，`EMAIL_FROM` 写 `店名 <bookings@你的域名>`
4. 还没有域名：`EMAIL_FROM` 先写 `Tempo <onboarding@resend.dev>`，这时只能发到你自己的邮箱，适合测试
5. 不填 `RESEND_API_KEY` 也能正常预约，只是不发邮件

### 第 5 步：前一天提醒邮件（GitHub Actions，免费）
仓库里已经有 `.github/workflows/reminders.yml`，每小时自动运行一次。
1. GitHub 仓库 → **Settings → Secrets and variables → Actions → New repository secret**
   - `SITE_URL`：你的网址（不要以 `/` 结尾）
   - `CRON_SECRET`：和 Netlify 里一样的值
2. **Actions** 页面里可以手动点 **Run workflow** 测试一次

> Supabase 免费项目一周没有任何访问会自动暂停。每小时的提醒任务会访问一次数据库，一般可以避免暂停；如果真的被暂停，在 Supabase 后台点一下恢复就行。

## 上线后怎么用

### 你（平台管理员）
1. 用 `PLATFORM_ADMIN_EMAILS` 里的邮箱注册并登录，打开 `/admin`
2. **邀请码 → 新建**，备注写店名，把生成的邀请链接发给已经谈好的店
3. 没有邀请码自己注册的店，提交后会出现在“待审核”，你检查后点“通过，上线”

### 店主
1. 打开邀请链接注册 → 填店名、链接、地址、时区 → 创建
2. 按“开店清单”走一遍：服务和价格 → 员工和技能 → 排班 → 营业时间 → 外观
3. 点“提交审核”（用邀请码的店直接上线）
4. 在“预约链接”页面复制链接、下载二维码，放到 Instagram、Google 地图、门口

### 技师
店主在“员工”页面输入技师的邮箱发邀请，技师用这个邮箱注册后，打开手机就能看到“我的日程”。

## 本地开发

```bash
npm install
cp .env.example .env.local
# 只填 DATABASE_URL 和 DIRECT_DATABASE_URL（可以用本地 Postgres），再加一行：
# DEV_FAKE_AUTH=1        ← 不用 Supabase，输入邮箱就能登录
# PLATFORM_ADMIN_EMAILS=admin@example.com
npm run db:migrate
npm run dev
```
打开 http://localhost:3000 。开发模式下没有配置 Supabase 时，图片会存在 `.uploads/` 文件夹，邮件内容会打印在终端里。

### 示范店
```bash
DATABASE_URL=postgres://… node scripts/seed-demo.mjs demo-nails 你的邮箱
```
生成一家已上线的“Demo Nails”：3 位技师、5 个服务、3 周排班，可以直接打开 `/demo-nails` 试约。

### 测试
```bash
npm run typecheck                                # 类型检查
DATABASE_URL=postgres://…/tempo_test npm test    # 见下（会清空这个测试库）
npm run e2e                                      # 浏览器全流程 + 无障碍检查
```
- **随机对照测试**（`tests/engine.property.test.ts`）：随机生成上千种排班、预约、设备、规则组合，和一个逐分钟检查的“笨办法”对照：系统推荐的时间必须正好等于规则允许的时间，不多也不少。`PROPERTY_RUNS=8000` 可以跑更多
- **数据库测试**：并发抢同一个时间、设备抢占、散客留位、爽约限制、候补通知、真实时长统计、纸本试算、每晚自检
- **浏览器测试**：开店 → 审核 → 预约 → 改时间 → 取消；作品集 → 约这个款 → 预约前问题 → 候补 → 客人确认 → 开始 / 完成 → 试点数据页；每个页面跑 axe 无障碍检查（WCAG 2.1 AA）
- **压力测试**（只对测试库）：
  ```bash
  npm run build
  LOADTEST_DISABLE_RATE_LIMIT=1 DATABASE_URL=… npx next start -p 3200   # 保持运行，另开一个终端执行下一行
  DATABASE_URL=… node scripts/loadtest.mjs http://localhost:3200 demo-nails 40
  ```
  40 个客人同时抢同一个时间，只有能做的人数那么多会成功，其余收到“刚被约走”，不能出现服务器错误或重复预约。**正式网站绝对不要设置 `LOADTEST_DISABLE_RATE_LIMIT`。**

## 代码结构

```
db/migrations/        数据库表结构（含防重复预约约束）
scripts/migrate.mjs   建表脚本
src/lib/engine.ts     可用时间计算（纯函数，前后端共用）
src/lib/bookings.ts   创建 / 修改 / 取消预约（事务 + 并发保护）
src/lib/availability.ts  从数据库组装某几天的可约时间
src/lib/data/         店铺、服务、员工、排班、报表、设备、作品集、候补、试点数据的数据库读写
src/lib/replay.ts     纸本试算：用今天的设置重排历史预约
src/lib/waitlistNotify.ts  取消后通知候补
docs/试点手册.md       三家店的现场试点手册
src/lib/email.ts      邮件模板和发送
src/lib/i18n/         中英文文案
src/app/[slug]/       客人看到的店铺页、预约流程、找回预约
src/app/b/[token]/    客人的预约管理页（改时间、取消）
src/app/dashboard/    店主后台
src/app/admin/        平台管理员后台
src/app/api/          给前端用的接口、提醒邮件定时任务
tests/  e2e/          自动测试
```
